# Portfolio 5 - Distributed exercise (6 marks)
Implemented design: two local PostgreSQL containers; a logical publication/subscription of a dedicated synthetic replication_probe table. The runner creates matching table DDL, a replication-only login, a publication and subscription, inserts a token on the primary, polls the subscriber, disables subscription, inserts another token, verifies it is absent while paused, re-enables and checks catch-up. Captures pg_stat_subscription/pg_publication/pg_subscription with connection strings excluded. The probe is a safe isolated demonstration, not replication of the whole financial schema or an HA service.

Logical replication is asynchronous: a committed primary row may be temporarily absent from the subscriber; a primary outage prevents new writes. The subscriber is a writable PostgreSQL server, so permissions must prevent competing writes in a real read-model deployment. DDL and sequences are not replicated automatically. This does not demonstrate physical standby, automatic failover, cloud deployment or zero data loss. Local containers share a host and cannot demonstrate zone resilience.

Proposed cloud topology: primary and physical standby across zones, synchronous acknowledgement if the latency/availability trade-off is acceptable, fenced writer failover, least-privilege TLS connections and encrypted backups with PITR. Async replication improves write availability but risks losing recent acknowledged writes during failover. Synchronous quorum can block writes if quorum is unavailable. CAP consistency/availability trade-offs concern network partitions, not a blanket choice of two features for every normal operation. Test recovery point and recovery time objectives before promising them.

Sharding by wallet introduces cross-shard transfer coordination; begin with time partitioning for large audit/event tables and proper indexes before sharding the ledger. Immutable ledger entries ease reconciliation but do not eliminate distributed transaction problems. Backups and replication solve different failures: replicated accidental deletion is not an independent backup.
