# Portfolio 2 - Query processing and optimisation (7 marks)
Run after P1. The runner adds 60,000 synthetic balanced transfers using the same posting function, then assigns reproducible timestamps during controlled bulk-load setup before restoring immutability. This setup is not exposed to the application role. It captures eight query result sets, raw EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) plans, and two separate five-trial before/after comparisons (time-range lookup and high-value lookup). Base PK/FK/ledger indexes remain in both conditions. Optional indexes are removed before baseline and added for the optimised runs. A warm-up is excluded. Results are checked for equality. The experiment is single-machine and sequential by condition: cache drift and background load limit causal conclusions. No simulated timing is used.

Gate: JSON plan and actual results exist; generated analysis states measured medians, row counts and limitations. An index can be slower for small tables or broad predicates; report that outcome without changing planner settings to manufacture a benefit.
